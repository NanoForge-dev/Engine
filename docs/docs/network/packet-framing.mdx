# Packet Channels

Every packet is sent on one of four channels. Pick the channel by what the
packet needs: whether it may be lost, and whether an older packet is still
useful once a newer one has arrived.

| Channel               | Lost?    | Order                    | Carried by          | Typical use                    |
| --------------------- | -------- | ------------------------ | ------------------- | ------------------------------ |
| `reliableOrdered`     | Never    | Send order               | TCP WebSocket       | Join, chat, game events        |
| `reliableUnordered`   | Never    | No promise               | TCP WebSocket       | Independent one-off messages   |
| `unreliableOrdered`   | Possibly | Late packets are dropped | WebRTC data channel | Positions, snapshots           |
| `unreliableUnordered` | Possibly | Any order                | WebRTC data channel | Fire-and-forget effects, pings |

The reliable channels need a TCP port (`SERVER_TCP_PORT` / `LISTENING_TCP_PORT`),
the unreliable ones a UDP port (`SERVER_UDP_PORT` / `LISTENING_UDP_PORT`).
Using a channel whose port is not configured throws.

Over TCP, `reliableUnordered` is delivered in order in practice: it only
promises that nothing is lost.

## Framing

Both transports deliver whole messages, so one message is one packet: there is
no delimiter and payloads may contain any bytes.

- **TCP**: each binary WebSocket frame starts with one tag byte, `0` for
  `reliableOrdered` and `1` for `reliableUnordered`, followed by the payload.
  Text frames are reserved for control messages such as the server `welcome`.
- **WebRTC**: the client opens one data channel per unreliable channel, labelled
  `unreliable-ordered` and `unreliable-unordered`. Both use `ordered: false` and
  `maxRetransmits: 0`.

## Dropping late packets

`unreliableOrdered` packets start with a big-endian `uint32` sequence number,
counted per peer and per direction. The receiver delivers a packet only if it is
newer than the last one it delivered, and drops it otherwise. Nothing ever waits
for a lost packet: a gap is skipped as soon as a newer packet arrives. Numbers
are compared as serial numbers, so the counter can wrap around.
